# 검증 기록

검증일: 2026-09-25. Linux ARM64 환경에서 수행했습니다.

## 프로젝트 문서 초기화·동기화

Codex Project Init의 inspect/check와 실제 진입점·설정·저장소·UI 코드 확인을
바탕으로 기여 지침, 편집 규칙, 설계 결정, 운영 런북과 참조 색인을 정리했습니다.
macOS 소스 설치와 현재 한/영·저장소 동작도 기존 문서에 반영했습니다.

문서 구조·로컬 링크 검사와 `git diff --check`가 통과했습니다. 문서만 변경한
첫 패키지 단계에서는 공개 문서 링크 143개와 기존 런타임 파일 22개의 동일한
SHA-256을 확인했습니다. 새 공개 문서 7개도 패키지에 포함됩니다.

이어진 사용자 요청으로 앱 표시 제목을 `my-agent-ops`로 변경했습니다. 사이드바,
브라우저 탭, 하단과 한/영 화면 문구에 적용하며 설치 패키지명 `agent-ops-local`,
CLI 명령과 데이터 경로의 `agent-ops` 식별자는 계속 사용합니다. 아래의 기존
버전별 테스트와 운영 실측 기록은 당시 결과로 보존합니다.

제목 변경은 별도 소스 복사본에서 `npm run check`로 검증했고 636개 테스트와
타입 검사·빌드가 통과했습니다. 브라우저 동선 20개도 통과했으며, 한글·영문
전환과 페이지 이동 후 브라우저 제목 유지, 사이드바 폭과 모바일 메뉴를
추가 확인했습니다. 새 빌드의 서버 파일은 기존 운영 빌드와 SHA-256이 동일합니다.
독립적인 운영 의존성 설치에서도 패키지 검증이 통과했습니다. 화면 파일 반영과
서비스 재시작 후 실제 `/proxy/4327/` 경로의 HTML 제목은 `my-agent-ops`였고,
제공된 JS는 검증한 빌드와 일치했습니다. HTML·JS·health 응답은 모두 정상입니다.

- 미저장 설정·검색 조건 유지, 대화·스킬 원문과 사용자 이름 보존.
- 완료 알림이 bootstrap 요청과 겹칠 때 한 번 더 갱신하는 큐.
- Agent Ops 자체 자식 프로세스의 동기화·취소·출력 제한과 상태 조회 응답성.
- DB 쓰기 잠금 중 상태 조회를 유지하고 메모·설정 변경을 비동기로 재시도.

- 여러 소스의 중복 이력에서 최신 기록 보존과 동일 원본의 정상적인 수정 반영.
- 압축 검색 본문과 한글·기호 검색, 이모지 제목, 기존 사용자 정보 보존.
- 백업 복원, 연결 파일을 통한 잠금 우회 거절, 스키마·버전 변경의 원자적 처리와
  VACUUM 이후에도 세션 ID에 연결되는 검색 결과.

소켓·자식 프로세스 검증은 실행 샌드박스 밖에서 수행했습니다. 샌드박스 안에서는
단순 Node 자식 프로세스의 표준출력도 비어 나오는 제약을 별도 최소 예제로
재현했습니다. 테스트 데이터·프로세스는 격리된 임시 자료이며 실제 모델 호출은
하지 않았습니다.

운영 의존성만 설치한 별도 경로에서 `agent-ops-local-1.1.1.tgz`의 실행·검색·
내보내기·데모 차단·오프라인 백업 최적화와 번들 자체의 별도 동기화 프로세스를
검증했습니다. `/proxy/4327/` 경로에서도 영문 전환과 `202` 동기화 접수를
추가 확인했습니다.

실제 대용량 캐시에서는 기존 FTS 본문을 재토큰화하는 무결성 검사가 오래 걸리는
것을 확인했습니다. 원본 변환 전 해당 검사를 중단하고 서비스를 복구한 뒤,
일반·검색 저장 테이블을 직접 검사하도록 개선했습니다. 같은 캐시의 15개
테이블을 읽기 전용으로 검사하는 데 4.071초가 걸렸습니다. 손상된 기존 검색
포스팅도 보존된 본문으로 재생성하는 회귀 테스트를 추가했습니다.

사용자 승인 후 실제 캐시의 검색 문서 9,971개를 변환하고 공간을 회수했습니다.
기존 대화·메모 등의 행 수는 변환 전후 검증했고, 스키마 4로 전환했습니다.

| 항목 | 변경 전 | 변경 후 |
|---|---:|---:|
| 활성 DB 파일 | 6,936,174,592 bytes | 4,408,213,504 bytes |
| 검색용 본문 | 2,624,758,229 bytes | 1,180,110,945 bytes |

활성 DB는 **36.45%**, 검색 본문은 **55.04%** 줄었습니다. 복원 검증을 마친
gzip 백업 **2,991,037,865 bytes**는 600 권한으로 별도 보관합니다. 백업을
포함하면 두 파일의 합계는 약 **7.40GB**입니다. 백업을 자동 삭제하지 않았으므로
활성 DB 감소량을 전체 디스크 사용량 감소로 해석하지 않습니다.

09:26 UTC의 실제 서비스 확인에서 1.1.1이 실행 중이었고, 루프백과 기존 프록시의
대상 주소 모두 HTTP 200을 반환했습니다. 첫 health 요청은 31ms, 동기화 중
추가 5회는 1–2ms였으며 bootstrap은 1.914초였습니다. 이 값은 해당 시점의
관측값이며 모든 검색·작업의 지연 시간을 보장하지 않습니다. 프록시 접두 경로의
화면·JS 파일은 검증한 빌드와 일치했고 한/영 전환 문구를 확인했습니다.
외부 비인증 요청은 기존 로그인으로 302 리다이렉트됐습니다.

## 검증의 범위

실제 유료 모델 호출은 수행하지 않았습니다. 실행 테스트는 원래 CLI 대신
입력·출력·종료를 제어할 수 있는 로컬 프로그램을 사용합니다. 실제 설치된
CLI의 도움말과 설치 상태, 원본 이력 읽기는 별도로 확인했습니다.

CLI 설치 확인은 인증 확인이 아닙니다. 계정별 로그인, 요금제, 모델 접근 권한,
프로젝트별 훅·MCP 설정은 실제 실행 환경의 조건을 따릅니다.

EC2에서 systemd로 라이브 서버를 시작한 뒤 루프백과 code-server의 대상 주소
`0.0.0.0:4327`에 대해 HTTP 200 응답을 확인했습니다. 리스너는
`127.0.0.1:4327`이며 서비스는 활성화·실행 상태입니다. 재부팅 자체는 수행하지
않았습니다. CloudFront의 캐시 비활성화와 모든 뷰어 헤더·쿠키·쿼리 전달 정책은
읽기 전용으로 확인했습니다.

외부 CloudFront 경로의 비인증 요청은 기존 code-server 로그인으로
리다이렉트됐습니다. 자동 승인 검토가 저장된 비밀번호를 이용한 외부 로그인
검증을 거부했으므로, 이 결과를 로그인 이후의 외부 브라우저 검증으로
간주하지 않습니다. 프록시 브라우저 테스트에는 임시 데모와 로컬 프록시만
사용했습니다.

온라인 `npm audit`는 이 환경의 자동 승인 검토에서 의존성 메타데이터의 외부
전송을 허용하지 않아 실행하지 못했습니다. 공개 보안 공지와 핵심 패키지의
버전을 대조했으며, 이를 전체 의존성에 취약점이 없다는 보증으로 취급하지

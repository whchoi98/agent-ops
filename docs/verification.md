## 1.1.1 한/영 화면·저장소 성능 검증

단위·통합 테스트 **636개(38개 파일)**, TypeScript 검사와 운영 빌드가
통과했습니다. Chromium 사용자 동선 **20개**도 통과했습니다.

- 테마 옆 한/EN 전환, 기본 한국어, 브라우저 언어 저장과 문서 언어 변경.
- 8개 화면의 영문 메뉴·설정·상태 표시, 모바일 배치와 테마 호환.
- 미저장 설정·검색 조건 유지, 대화·스킬 원문과 사용자 이름 보존.
- 완료 알림이 bootstrap 요청과 겹칠 때 한 번 더 갱신하는 큐.
- Agent Ops 자체 자식 프로세스의 동기화·취소·출력 제한과 상태 조회 응답성.
- DB 쓰기 잠금 중 상태 조회를 유지하고 메모·설정 변경을 비동기로 재시도.
- Kiro 행별 지문 지속성, 변경된 메시지만 저장, 같은 검색 본문 재작성 생략.
- 여러 소스의 중복 이력에서 최신 기록 보존과 동일 원본의 정상적인 수정 반영.
- 압축 검색 본문과 한글·기호 검색, 이모지 제목, 기존 사용자 정보 보존.
- 백업 복원, 연결 파일을 통한 잠금 우회 거절, 스키마·버전 변경의 원자적 처리와
  VACUUM 이후에도 세션 ID에 연결되는 검색 결과.

소켓·자식 프로세스 검증은 실행 샌드박스 밖에서 수행했습니다. 샌드박스 안에서는
단순 Node 자식 프로세스의 표준출력도 비어 나오는 제약을 별도 최소 예제로
재현했습니다. 테스트 데이터·프로세스는 격리된 임시 자료이며 실제 모델 호출은
하지 않았습니다.

운영 의존성만 설치한 별도 경로에서 `agent-ops-local-1.1.1.tgz`의 실행·검색·
내보내기·데모 차단·오프라인 백업 최적화와 번들 자체의 별도 동기화 프로세스를
검증했습니다. `/proxy/4327/` 경로에서도 영문 전환과 `202` 동기화 접수를
추가 확인했습니다.

실제 대용량 캐시에서는 기존 FTS 본문을 재토큰화하는 무결성 검사가 오래 걸리는
것을 확인했습니다. 원본 변환 전 해당 검사를 중단하고 서비스를 복구한 뒤,
일반·검색 저장 테이블을 직접 검사하도록 개선했습니다. 같은 캐시의 15개
테이블을 읽기 전용으로 검사하는 데 4.071초가 걸렸습니다. 손상된 기존 검색
포스팅도 보존된 본문으로 재생성하는 회귀 테스트를 추가했습니다.

|---|---:|---:|

두 번째 수집까지 반영한 최종 저장 세션은 **9,820개**입니다. 검증 중에도 원본

## 검증의 범위

실제 유료 모델 호출은 수행하지 않았습니다. 실행 테스트는 원래 CLI 대신
입력·출력·종료를 제어할 수 있는 로컬 프로그램을 사용합니다. 실제 설치된
CLI의 도움말과 설치 상태, 원본 이력 읽기는 별도로 확인했습니다.

CLI 설치 확인은 인증 확인이 아닙니다. 계정별 로그인, 요금제, 모델 접근 권한,
프로젝트별 훅·MCP 설정은 실제 실행 환경의 조건을 따릅니다.

EC2에서 systemd로 라이브 서버를 시작한 뒤 루프백과 code-server의 대상 주소
`0.0.0.0:4327`에 대해 HTTP 200 응답을 확인했습니다. 리스너는
`127.0.0.1:4327`이며 서비스는 활성화·실행 상태입니다. 재부팅 자체는 수행하지
않았습니다. CloudFront의 캐시 비활성화와 모든 뷰어 헤더·쿠키·쿼리 전달 정책은
읽기 전용으로 확인했습니다.

외부 CloudFront 경로의 비인증 요청은 기존 code-server 로그인으로
리다이렉트됐습니다. 자동 승인 검토가 저장된 비밀번호를 이용한 외부 로그인
검증을 거부했으므로, 이 결과를 로그인 이후의 외부 브라우저 검증으로
간주하지 않습니다. 프록시 브라우저 테스트에는 임시 데모와 로컬 프록시만
사용했습니다.

온라인 `npm audit`는 이 환경의 자동 승인 검토에서 의존성 메타데이터의 외부
전송을 허용하지 않아 실행하지 못했습니다. 공개 보안 공지와 핵심 패키지의
버전을 대조했으며, 이를 전체 의존성에 취약점이 없다는 보증으로 취급하지
않습니다. 오프라인 audit 출력도 그러한 보증으로 사용하지 않았습니다.

배포 시 `npm pack`으로 만든 파일을 별도의 임시 설치 경로에 설치하고,
CLI 도움말·데모 시작·HTTP 응답·검색·내보내기·실행 차단을 확인합니다.
Node.js 20.20.1 환경의 별도 운영 의존성 설치에서 이 검증을 통과했습니다.
검증 서버의 PATH에서 세 CLI를 제외한 상태에서도 모든 데모 미리보기가
동작했고, 실제 실행은 차단됐습니다.

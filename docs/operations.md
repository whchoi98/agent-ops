# 운영 가이드

## 구성

```text
브라우저 ── 같은 출처 HTTP/SSE ── Fastify
                                  ├─ 세션 검색 / 정리 / 내보내기
                                  ├─ SQLite 저장소 + FTS5
                                  ├─ 별도 sync 프로세스의 읽기 전용 수집기
                                  │    ├─ Codex JSONL
                                  │    ├─ Claude Code JSONL
                                  │    └─ Kiro JSON / JSONL / SQLite
                                  └─ 실행 대기열
                                       ├─ codex
                                       ├─ claude
                                       └─ kiro-cli
```

UI는 빌드 시 정적 파일로 생성됩니다. 서버와 UI가 같은 출처를 사용하므로
별도의 CORS 서버나 프런트엔드 호스팅이 필요하지 않습니다.

## 데이터와 백업

기본 데이터 디렉터리:

```text
~/.local/share/agent-ops/
  agent-ops.sqlite
  agent-ops.sqlite-wal
  agent-ops.sqlite-shm
  server.lock
  server-lock.sqlite
  sync-lock/
    server-lock.sqlite
  backups/
    agent-ops-before-optimize-*.sqlite.gz
  demo/
    agent-ops.sqlite
```

`AGENT_OPS_DATA_DIR` 또는 `--data-dir`은 저장소의 기준 경로를 변경합니다.
데모는 기준 경로 아래 `demo`를 사용합니다. 라이브와 데모 저장소의 모드
표시를 검증하므로 서로 다른 모드의 데이터 파일을 잘못 열지 않습니다.

데이터베이스에는 원본 대화, 프롬프트, 메모가 포함될 수 있습니다. 데이터 파일은
600 권한으로 만들고 새 데이터 디렉터리는 700 권한으로 만듭니다. 기존
디렉터리를 지정할 때에는 해당 디렉터리의 접근 권한도 확인하세요.
my-agent-ops DB 파일의 심볼릭 링크나 하드 링크는 허용하지 않습니다. 저장소를
옮길 때는 파일을 복사해 별도 데이터 디렉터리의 잠금과 DB가 함께 유지되게 합니다.

백업은 서버를 `Ctrl+C`로 종료한 뒤 데이터 디렉터리를 복사하는 방식이
간단합니다. 실행 중인 SQLite의 주 파일 하나만 복사하면 WAL의 최신 변경이
빠질 수 있습니다. 원본 에이전트 세션은 my-agent-ops가 삭제하지 않습니다.

복원은 서버를 종료하고 같은 모드의 데이터 디렉터리를 복사한 뒤 재시작합니다.
이전 버전으로 내릴 때 데이터베이스 스키마가 더 새로우면 실행을 거절합니다.

### 저장 공간 최적화

`agent-ops optimize`는 my-agent-ops 캐시의 검색용 본문을 압축하고 빈 페이지를
회수합니다. 대화·메모·태그·북마크를 삭제하지 않으며 Kiro의 원본
`data.sqlite3`도 변경하지 않습니다. 신규 캐시는 압축 검색 저장소를 사용합니다.
기존 캐시는 서버 시작 시 대규모 변환을 하지 않고, 아래 명령으로 전환합니다.

```bash
# 터미널 서버는 Ctrl+C, systemd 서버는 서비스 중지 후 실행합니다.
agent-ops optimize --data-dir "$HOME/.local/share/agent-ops"
agent-ops --data-dir "$HOME/.local/share/agent-ops"
```

서버 또는 별도 동기화가 같은 저장소를 사용하면 작업을 거절합니다. 먼저 SQLite의
일관된 스냅샷을 만들고 gzip 백업을 복원 스트림의 SHA-256으로 검증한 뒤 변환합니다.
일반 테이블·검색 저장 테이블·빈 페이지의 구조를 검사하고, 변환할 본문의 UTF-8을
확인합니다. 재생성할 기존 FTS 색인 전체를 다시 토큰화하는 검사는 생략합니다.
결과는 변경 전·후 활성 데이터 크기, 검색 본문의 압축 크기, 백업 경로와 크기를
JSON으로 출력합니다. 백업은 데이터 디렉터리의 `backups/`에 600 권한으로
남습니다. 임시 스냅샷과 압축·공간 회수를 위해 현재 DB 크기의 3배 + 128 MiB 이상
여유 공간을 요구하며 큰 저장소에서는 완료까지 시간이 걸립니다.

변환 후 스키마는 4입니다. 스키마 3까지만 지원하는 이전 실행 파일로 되돌릴
때는 서버를 종료하고 압축 백업을 **새 데이터 디렉터리**에 복원합니다.
기존 WAL/SHM과 복원한 DB를 섞지 마세요.

```bash
mkdir -m 700 ./restored-agent-ops
gzip -dc /absolute/path/to/agent-ops-before-optimize-....sqlite.gz \
  > ./restored-agent-ops/agent-ops.sqlite
chmod 600 ./restored-agent-ops/agent-ops.sqlite
agent-ops --data-dir ./restored-agent-ops
```

압축은 본문 중복을 줄이는 방식이며 저장 용량의 상한을 설정하지는 않습니다.
새 기록은 계속 쌓이고 백업도 별도 공간을 차지합니다. 자동 보존 기간이나 과거
데이터 삭제는 적용하지 않습니다.

## 수집

동기화는 시작 시와 설정된 주기마다 실행됩니다. 같은 시점에 들어오는 수동
동기화 요청은 하나의 작업을 공유합니다. 파일 변경 여부를 비교하여 수정된
기록만 다시 읽으며, 원본 세션의 ID를 기준으로 갱신합니다. 갱신 시 사용자
제목, 북마크, 태그, 메모는 유지합니다.

실제 이력의 파싱과 SQLite 쓰기는 앱이 소유한 `agent-ops sync` 자식 프로세스에서
실행합니다. HTTP 서버는 동기화 결과와 진행 알림을 받아 화면을 갱신하며,
종료할 때 소유한 동기화 프로세스도 정리합니다. Kiro SQLite는 행별 지문을
저장해 DB의 다른 설정이 바뀌어도 같은 대화를 다시 정규화·저장하지 않습니다.
변경된 대화에서도 달라진 메시지만 갱신하고 검색 본문이 같으면 색인을 재작성하지
않습니다. 최초 지문 생성 시에는 기존 기록을 한 번 확인해야 합니다.

화면의 동기화 버튼은 `POST /api/sync/start`로 시작을 요청하고 `202` 응답을
바로 받습니다. 진행 상태는 bootstrap과 SSE로 갱신하므로 긴 수집 작업 동안
브라우저 요청을 계속 열어 두지 않습니다. 기존 `POST /api/sync`는 완료 결과를
기다리는 API로 유지합니다.

세션 정리·프로젝트·템플릿·설정 변경은 SQLite 쓰기 잠금이 있으면 이벤트 루프를
양보하며 최대 5초 재시도합니다. 각 시도는 트랜잭션으로 처리하고 실패한 시도의
부분 변경을 남기지 않습니다.

홈 디렉터리 전체를 검색하지 않습니다. 설정에 지정된 경로만 읽습니다.
심볼릭 링크를 따라 원본 범위를 확장하지 않으며 파일 크기·개수·깊이 제한을
적용합니다. 매우 큰 파일이나 형식이 다른 파일은 동기화 경고를 확인하세요.

원본에서 파일을 지워도 가져온 이력을 자동 삭제하지 않습니다. 이 설계는
일시적인 경로 변경이나 마운트 해제를 대화 삭제로 해석하지 않기 위한 것입니다.

Codex와 Claude Code의 사용량은 이벤트 중복을 정리하여 집계합니다. Kiro
버전과 저장 형식에 따라 토큰이 기록되지 않을 수 있습니다. 기록되지 않은
값은 미상으로 남겨 둡니다.

Claude Code의 하위 에이전트는 부모와 분리된 기록으로 보관합니다. 세션 정보에서
부모 기록을 열 수 있으며, CLI가 직접 재개할 수 없는 하위 기록은 작업 인계로
이어갑니다. 긴 JSONL은 512 MiB까지 스트리밍으로 읽습니다. 한 JSON 레코드와
SQLite 대화 값은 64 MiB, 정규화한 메시지는 세션당 20,000개로 제한하며 생략은
진단에 표시합니다. SQLite 데이터베이스 전체 크기를 64 MiB로 제한하지 않습니다.

모델별 집계는 세션에 마지막으로 기록된 모델을 기준으로 세션을 묶습니다.
한 세션에서 모델을 여러 번 바꾼 경우의 호출별 비용 배분을 뜻하지 않습니다.
도구 통계는 호출 이벤트를 세며 호출과 응답을 중복 집계하지 않습니다.

## 화면 언어

상단 테마 버튼 바로 옆의 **한/EN** 버튼으로 한국어와 영어를 전환합니다.
기본값은 한국어이며 선택은 해당 브라우저의 `agent-ops-language` 로컬 저장소에
기록됩니다. 사용자마다 다른 언어를 선택할 수 있고, 서버 설정을 저장할 필요가
없습니다. 대화·스킬 원문, 경로, 코드, 사용자가 입력한 이름과 메모는 번역하지
않습니다. 언어 전환 중 검색 조건이나 작성 중인 입력값도 유지합니다.
외부 CLI 로그와 사전에 없는 상세 진단 문구는 원문으로 남을 수 있습니다.

## 스킬·플러그인 조회와 분석

이 기능은 my-agent-ops 서버 머신의 설정과 파일을 읽습니다. Mac에서 실행하면
Mac의 확장 구성을, EC2에서 실행하면 EC2의 구성을 표시합니다.

| 어시스턴트 | 주요 조회 위치 |
|---|---|
| Codex | `$CODEX_HOME/skills`, `~/.agents/skills`, `/etc/codex/skills`, Codex 플러그인 캐시·`config.toml` |
| Claude Code | `$CLAUDE_CONFIG_DIR/skills`, `commands`, 플러그인 설치 레지스트리·캐시·동기화 폴더·설정 |
| Kiro | `~/.kiro/skills`, `~/.kiro/agents`, `~/.kiro/powers/installed` |
| 프로젝트 | 선택한 등록 프로젝트의 `.agents/skills`, `.codex/skills`, `.claude`, `.kiro` 구성 |

Codex의 프로젝트 설정은 사용자 설정에서 해당 프로젝트의 신뢰를 확인할 수
있을 때 적용합니다. Claude의 로컬 프로젝트 설정은 공유 프로젝트·사용자
설정보다 우선합니다. 모든 CLI의 세션 인수, 활성 프로필, 조직 정책과 현재
동기화 계정까지 재현하는 기능은 아닙니다.

목록은 설정상 활성·비활성, 발견한 스킬, 미확인 상태와 캐시를 구분합니다.
설치만 확인한 Power의 CLI 활성화나 실제 사용 횟수를 추정하지 않습니다.
Kiro 에이전트의 `skill://` 참조는 연결 근거로 표시하며 호출 증거로 취급하지
않습니다. 선택한 프로젝트 경로의 정의를 조회하며 모든 하위 작업 디렉터리의
동적 설정을 자동으로 재현하지 않습니다.

상세 화면은 목적, 트리거, 선언된 도구, MCP 서버, 훅, 문서 구조와 참조 파일을
로컬에서 분석합니다. 원문과 텍스트 파일은 민감한 키·환경 변수 값을 마스킹해
표시합니다. 선언된 도구 목록은 실제 실행 권한을 보증하지 않습니다.

조회는 알려진 확장 경로로 제한하고 인증 파일, 데이터베이스, 범위 밖의
심볼릭 링크와 바이너리 본문을 제외합니다. 항목은 최대 2,000개, 상세 파일
목록은 최대 160개, 텍스트 미리보기는 파일당 128 KiB입니다. 생략·접근 오류는
진단에 표시합니다. 전역 조회 결과는 최대 60초간 캐시되며 **목록 새로고침**으로
다시 읽을 수 있습니다. 확장 내용을 설치·수정·실행하는 API는 없습니다.

**CLI 분석 작업 준비**는 마스킹된 원문과 구조 분석을 읽기 전용 작업의
프롬프트로 준비합니다. 기존 새 실행 화면에서 프로젝트·에이전트·프롬프트를
검토하고 명령 미리보기 후 실행합니다. 이때의 인증·모델 사용은 해당 CLI를
따릅니다. 데모에서는 미리보기까지만 가능하며 실제 실행은 차단됩니다.

형식 근거: [Codex 스킬](https://learn.chatgpt.com/docs/build-skills),
[Codex 플러그인 설정](https://learn.chatgpt.com/docs/config-file/config-reference),
[Claude Code 스킬](https://code.claude.com/docs/en/skills),
[Claude Code 플러그인](https://code.claude.com/docs/en/plugins-reference),
[Kiro 스킬](https://kiro.dev/docs/skills/),
[Kiro Powers](https://kiro.dev/docs/powers/installation/).

## CLI 현재·최신 버전 비교

설정의 **CLI 버전 비교**에서 Codex, Claude Code, Kiro의 현재 설치 버전과
최신 공개 배포 버전을 함께 확인합니다. 확인 시각과 공식 출처를 표시하고,
결과를 캐시해 반복 요청을 줄입니다. **최신 버전 확인**으로 다시 조회할 수
있으며 CLI 업데이트를 실행하는 기능은 아닙니다.

최신 버전은 공개 HTTPS 메타데이터에서 읽습니다. 로컬 버전 문자열,
프로젝트·설정·인증 정보는 요청에 포함하지 않습니다. 네트워크가 차단되거나
응답을 해석하지 못하면 최신 여부를 **확인 실패**로 표시하며, 확인 가능한
현재 버전은 유지합니다.

프리릴리스와 별도 배포 채널은 공개 기본 배포보다 버전이 높을 수 있습니다.
이를 다운그레이드 대상으로 표시하지 않습니다. 표시는 버전 문자열의 비교이며
조직의 업데이트 정책이나 설치 방식까지 변경하지 않습니다. 데모의 버전은
화면 동작을 설명하기 위한 고정 예시입니다.

조회 출처는 Codex의 공식 `@openai/codex` npm latest, Claude Code의 공식
`@anthropic-ai/claude-code` npm latest, Kiro의 공식 stable CLI 매니페스트입니다.
Kiro IDE 버전이나 선택형 프리릴리스 채널을 stable CLI 버전과 혼동하지 않습니다.

## 실행 권한

my-agent-ops는 셸을 통해 문자열 명령을 실행하지 않습니다. 정해진 에이전트
실행 파일과 인수 배열을 사용하고, 서버에서 프로젝트와 요청을 검증합니다.
프롬프트와 이력에 적힌 텍스트를 운영 명령으로 해석하는 API는 없습니다.

| 정책 | 의미 |
|---|---|
| 읽기 전용 | 각 CLI의 읽기 전용 샌드박스 또는 제한된 읽기 도구 정책 |
| 워크스페이스 쓰기 | 선택한 프로젝트 작업을 위한 CLI 쓰기 도구 정책 |

세 CLI의 격리 기능은 같지 않습니다. Codex의 샌드박스와 Claude/Kiro의 도구
권한 정책을 같은 운영체제 수준의 격리라고 해석하지 마세요. 설치된 CLI의
구성, 훅, MCP, 자격 증명은 해당 CLI가 관리합니다. 실행 전 미리보기에
표시되는 실제 옵션과 설명을 확인할 수 있습니다.

샌드박스·승인 우회 또는 모든 도구 신뢰 옵션은 생성하지 않습니다. 비대화형
실행에서 허용하지 않은 도구는 거절되거나 CLI가 오류를 반환할 수 있습니다.

Claude/Kiro로 테스트·빌드 명령까지 실행하려면 워크스페이스 쓰기를 선택한 뒤
**터미널 명령 허용**을 켭니다. 기본값은 꺼짐이며, 실행 전에 명령 미리보기에서
추가된 셸 도구 권한을 확인합니다. 이 옵션은 CLI의 셸 도구를 허용하는 것으로
운영체제 수준에서 프로젝트 밖의 접근을 격리하는 기능은 아닙니다. Codex의
명령 실행은 선택한 샌드박스 정책을 따릅니다.

## 대기열과 복구

최대 동시 실행 수는 1–8개, 시간 제한은 1–240분으로 설정할 수 있습니다.
같은 실제 프로젝트 경로의 작업은 순차 실행합니다. 시작 시점에 프로젝트
존재 여부와 실행 허용을 다시 검사합니다.

로그는 표준 출력·표준 오류·운영 이벤트로 구분합니다. 로그 저장량은 제한되며,
제한을 넘으면 생략되었다고 표시합니다. 이벤트 스트림을 다시 연결한 뒤에도
저장된 로그와 종료 상태를 읽을 수 있습니다.

취소는 앱이 소유한 실행만 대상으로 합니다. 서버 종료 시 소유한 작업을
정리합니다. 예상치 못한 프로세스 종료 후 재시작하면 이전 대기·실행 작업을
중단됨으로 표시하고 사용자가 상태를 검토한 뒤 재실행하도록 합니다.

같은 데이터 디렉터리로 두 서버를 실행할 수 없습니다. 별도의 SQLite 파일에
운영체제 잠금을 유지하며, 프로세스가 비정상 종료되면 운영체제가 잠금을
해제합니다. `server.lock`은 진단용 메타데이터이고 잠금 소유권의 기준이
아닙니다. 별도 인스턴스가 필요하면 포트와 데이터 디렉터리를 모두 바꾸세요.

## 원격 머신에서 사용

### 인증된 웹 IDE 포트 프록시

CloudFront → ALB → EC2 → code-server의 `/proxy/4327/` 경로로 접속할 때에는
공인 EC2 주소가 필요하지 않습니다. 기존 게이트웨이 인증을 유지한 상태에서
외부 HTTPS URL을 명시합니다.

```bash
npm start -- --port 4327 --public-url https://YOUR_DOMAIN/proxy/4327/
```

`--public-url`은 허용할 브라우저 출처와 애플리케이션 기준 경로입니다.
`X-Forwarded-Host` 값에서 허용 출처를 자동으로 추측하지 않습니다. 앱의
리스너는 `127.0.0.1` 그대로이며, 이 옵션은 같은 머신의 **인증된 프록시**
뒤에서 사용하는 용도입니다. 앱 자체에 공개 인터넷용 로그인 기능을 추가하는
옵션이 아닙니다.

프록시가 접두 경로를 제거하는 경우와 그대로 전달하는 경우를 모두 지원합니다.
`/proxy/4327/api/…`, 정적 파일, 한글 글꼴, SSE가 같은 경로 아래에서 동작합니다.

터미널을 닫아도 실행을 유지하려면 `deploy/agent-ops.service`의 경로와 사용자를
환경에 맞게 확인한 뒤 systemd 서비스로 설치합니다. 서비스 환경 파일
`.data/service.env`에는 다음 값을 설정합니다.

```text
AGENT_OPS_PORT=4327
AGENT_OPS_PUBLIC_URL=https://YOUR_DOMAIN/proxy/4327/
```

```bash
sudo install -m 0644 deploy/agent-ops.service /etc/systemd/system/agent-ops.service
sudo systemctl daemon-reload
sudo systemctl enable --now agent-ops.service
sudo systemctl status agent-ops.service
```

환경 파일은 서버에만 보관하고 `600` 권한을 사용하세요. CLI가 별도의 인증
환경 변수를 요구하면 이 서비스 환경에도 설정해야 합니다. 사용자별 CLI 로그인
파일은 서비스를 실행하는 사용자 계정을 기준으로 읽습니다.

설정이나 빌드를 변경한 뒤에는 `sudo systemctl restart agent-ops`로 재시작합니다.
`sudo journalctl -u agent-ops -n 50 --no-pager`로 시작 오류를 확인할 수 있습니다.

### SSH 터널

서버를 원격 머신에서 실행한 뒤 로컬 터미널에서 포트를 전달합니다.

```bash
ssh -N -L 4317:127.0.0.1:4317 user@your-server
```

로컬 브라우저에서 `http://127.0.0.1:4317`로 접속합니다. 실행되는 CLI와
프로젝트 경로는 원격 머신 기준입니다.

## 내보내기와 인계

내보내기와 인계는 일반적인 API 키, 인증 헤더, 비밀번호 할당, 개인키
블록 등을 마스킹합니다. 형식이 알려지지 않은 비밀까지 완벽하게 탐지하는
기능은 아니므로 공유 전에 내용을 확인하세요. HTML 내보내기는 대화의
HTML을 실행하지 않으며 외부 리소스를 자동으로 가져오지 않습니다.

인계 프롬프트에는 원본 에이전트, 프로젝트, 최근 사용자·응답 메시지, 메모,
다음 작업을 포함합니다. 긴 대화는 길이 제한에 따라 줄이고 사용자에게
편집 가능한 프롬프트를 제공합니다. 새로운 실행을 누르기 전까지 모델
서비스에 전송하지 않습니다.

## 문제 해결

| 증상 | 확인할 내용 |
|---|---|
| CLI 미설치 | 서버 프로세스의 `PATH`, CLI 설치 위치, `agent-ops doctor` 결과 |
| 인증 오류 | 해당 CLI의 비대화형 인증 요구사항과 현재 로그인·환경 변수 |
| Kiro headless 인증 실패 | 설치된 Kiro 버전에 따라 `KIRO_API_KEY` 등 별도 headless 인증이 필요할 수 있음 |
| 세션이 보이지 않음 | 수집 경로, 파일 접근 권한, 동기화 경고, 검색 필터 |
| 비용이 `—`로 표시됨 | 원본 기록에 비용이 없음. 토큰에서 임의 비용을 계산하지 않음 |
| 작업이 대기 중 | 동시 실행 수, 같은 프로젝트의 다른 실행, 프로젝트 실행 허용 |
| 재개 실패 | 원본 세션 보존 여부, 에이전트와 프로젝트 일치, CLI 버전의 재개 지원 |
| 프록시에서 `ECONNREFUSED` | `systemctl status agent-ops`, 프록시 대상 포트와 `AGENT_OPS_PORT`, 로컬 `/api/health` 응답 |
| 출처/Host 오류 | 프록시 사용 시 `--public-url`의 실제 HTTPS 도메인·경로와 서비스 환경 파일, 로컬 사용 시 같은 `127.0.0.1` 주소 |
| 포트 사용 중 | `--port` 변경. 같은 저장소의 다른 서버가 실행 중이면 먼저 종료 |
| UI가 API 안내문만 표시 | `npm run build` 실행 또는 개발 서버 `npm run dev` 사용 |

## 검증 범위

단위·통합 테스트는 원본 형식을 모사한 비식별 자료와 임시 SQLite를 사용합니다.
실행 테스트는 실제 자식 프로세스를 시작하되 외부 모델 서비스 대신 제어 가능한
로컬 프로그램을 사용하여 인수, 표준 입력, 출력, 취소, 시간 초과와 복구를
검증합니다. 브라우저 테스트는 데모 모드만 사용합니다.

CLI 설치·도움말 및 실제 로컬 이력의 읽기 전용 수집은 모델 호출과 별도로
검증할 수 있습니다. 특정 계정의 인증, 유료 모델 응답 품질, 개별 프로젝트
훅의 동작은 해당 실행 환경에서 확인해야 합니다.

# 하니스 관리 설계

## 목적과 범위

my-agent-ops의 **분석 및 관리 > 하니스 관리**에서 AutoHarness의 설치 상태,
정책 조회와 편집, 정책 검증, 실제 엔진의 도구 호출 판정, 어시스턴트별 훅 설정과
감사 로그를 관리합니다. 도구 호출 판정은 입력을 실행하지 않습니다.

검토 기준은 AutoHarness `0.1.1`, 소스 커밋
`3561e468f9ca9f9bf282512e695bd32e4e90fef4`입니다. 기존 앱은 TypeScript,
Node.js 20.19 이상이며 AutoHarness는 선택 설치하는 Python 3.10 이상 엔진입니다.
Python이 없어도 앱과 정책, 기존 감사 로그 조회가 동작해야 합니다.

컨텍스트 압축이나 멀티에이전트 실행을 기존 CLI 내부에 삽입하는 기능은
이번 관리 메뉴의 기능으로 표시하지 않습니다. 기존 CLI 권한과 미리보기는
유지합니다.

## 사용자 동선

1. 새 메뉴에서 프로젝트를 고르고 엔진 상태, 발견한 정책과 훅 설정을 확인합니다.
2. Python 경로를 설정하고 엔진을 명시적으로 확인합니다. 설치되지 않았으면
   검증 기준을 고정한 설치 명령과 다시 확인하는 동선을 제공합니다.
3. 기본 정책이나 기존 정책을 읽고, 앱이 관리하는 정책을 편집하고 검증합니다.
   원본 정책은 읽기 전용이며 저장 시 예상 개정을 확인합니다.
4. 도구 이름과 JSON 입력을 보내 실제 AutoHarness 엔진의 판정과 이유를 봅니다.
   허용, 승인 필요, 차단, 엔진 오류를 구분하고 이 검사를 도구 실행으로 세지 않습니다.
5. 프로젝트별 Claude Code, Codex, Kiro IDE/CLI 훅 변경을 미리 보고 적용하거나
   앱이 추가한 설정만 제거합니다. 기존 설정은 백업하고 충돌 시 다시 확인합니다.
6. 프로젝트, 클라이언트, 도구와 판정으로 감사 기록을 찾습니다. 원본 전체가 아닌
   읽어서 보관한 범위의 건수임을 표시합니다.

화면은 엔진, 정책, 판정 테스트, 훅, 감사 기록 탭으로 나누며 탭을 바꿔도
작성 중인 입력을 유지합니다.

## 경계와 동작

- 새 API는 `/api/harness` 아래에 두고 기존 Host, Origin, 로컬 연결,
  `X-Agent-Ops: 1`, 프록시 경로 보호를 사용합니다.
- 모든 파일 경로는 서버가 결정합니다. 등록 프로젝트, 사용자 AutoHarness 설정,
  앱 전용 디렉터리 밖의 파일, 경계 밖 링크, 임의 파일 조회를 허용하지 않습니다.
- 정책은 제한된 YAML로 읽습니다. 별칭 확장, 과도한 크기와 깊이, 비정상 구조를
  거절하고 비밀 값을 가립니다. 가린 값을 원본에 덮어쓰는 편집은 제공하지 않습니다.
- 엔진 검사와 판정은 명시적인 POST에서만 시작합니다. Python은 절대 경로로
  `shell: false`와 격리된 import 경로를 사용하며 입력은 stdin JSON입니다.
  실행 시간, 입력, 출력, 동시 실행 수와 자식 프로세스 정리를 제한합니다.
- Python 브리지는 실제 엔진의 `evaluate()`를 호출합니다. 사용자가 검사한
  도구 명령은 실행하지 않습니다. 유효하지 않은 응답과 시간 초과를 허용으로
  변환하지 않습니다.
- 훅은 클라이언트별 공식 입력과 응답 형식으로 변환합니다. `ask`를 허용으로
  바꾸지 않으며 앱의 비대화형 실행에는 승인 필요 판정을 차단으로 전달합니다.
  Codex 훅의 신뢰 검토를 자동 우회하지 않습니다.
- 실제 승인 동선을 표현하지 못하는 Codex와 Kiro 사전 훅에서는 승인 필요
  요청을 차단하고 원래 판정 `ask`를 감사 기록에 보존합니다.
- 훅 설정됨과 실제 이벤트 관측됨은 별도 상태입니다. Kiro IDE 1.0과 CLI 3.0
  형식을 구분하고 설치 버전을 확인하지 못하면 지원 확인이 필요하다고 표시합니다.
- Kiro IDE와 CLI의 새 훅 디렉터리는 공유하므로 한 설정과 `kiro.json` 바인딩만
  관리합니다. 적용과 제거가 두 클라이언트에 영향을 준다고 표시하고, 출처를
  구별할 수 없는 실제 감사 이벤트는 공통 Kiro로 기록합니다.
- 판정 테스트와 훅 이벤트를 별도 감사 유형으로 기록합니다. 원본 입력, 출력,
  토큰이나 credit을 중복 저장하거나 추정하여 합산하지 않습니다.
- 감사 조회는 한도 안에서 보관 구간의 연속성을 검증하고 추가된 JSONL 기록을
  수집하며 회전, 잘림, 긴 줄과 부분 줄을 처리합니다.
  최근 기록 캐시의 기본 한도는 2,000개, 보관 기간은 30일입니다.
  앱 전용 로그는 회전과 크기 제한을 적용하고 외부 원본 로그는 삭제하지 않습니다.
- 데모는 합성 정책, 연결 상태와 감사 기록을 제공하며 외부 엔진 실행과 실제
  프로젝트 훅 변경을 차단합니다.
- 한국어와 영어, 밝은 테마와 어두운 테마, 모바일, 키보드 조작을 지원합니다.
- 기존 세션과 SQLite 스키마 4, README 설치 문구와 공개 릴리스 이력을 보존합니다.

## 구현 단위

- `shared/harness.ts`: API 및 화면 계약.
- `server/harness/policy.ts`, `io.ts`: 파일 경계, 발견한 정책과 앱 정책 저장.
- `server/harness/audit.ts`: 증분 조회와 보관한 범위의 집계.
- `server/harness/runtime.ts`, `bridge.py`: 실제 Python 엔진 호출과 정리.
- `server/harness/hooks.ts`: 클라이언트별 설정 미리보기, 적용과 제거.
- `server/harness/service.ts`, `routes.ts`: 등록 프로젝트와 설정을 연결하는 API.
- `src/pages/Harness.tsx`, `src/features/harness/`: 관리 화면과 요청 상태.
- `docs/reference/harness.md`: 한영 설치, 정책, 훅, 감사 및 문제 해결 안내.

## 완료 증거

파일 경계, 오래된 개정과 미리보기, 실제 엔진 판정, 차단/승인 응답, 기존 훅 보존,
프로세스 제한과 취소, 로그 증분 수집과 회전, 비밀 값 보호, 데모 격리를 검증합니다.
브라우저에서는 메뉴 진입부터 정책, 판정, 훅 미리보기와 감사 조회를 확인합니다.
전체 타입 검사와 회귀 테스트, 빌드, 설치 파일의 실행 검사를 통과한 뒤
버전, CHANGELOG, 태그와 릴리스를 맞추고 승인된 운영 환경에 반영합니다.
